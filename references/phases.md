# Office Hours Phase Guide

Use these phases when running the 0-1 Product Definition mode.

## Phase 0 - Stage and output check

Goal: understand maturity and choose the right depth.

Ask:

- “现在这是想法、原型、MVP、已有用户、增长阶段，还是要重构/转型？”
- “这次最想得到什么：PRD、MVP 定义、验证计划、路线图、投资人问答，还是完整产品定义包？”
- “你希望输出为 Markdown、DOCX、PPT、飞书文档结构，还是先只要正文？”

Exit when:

- Product stage is known.
- Desired output is known.
- Any required industry lens is selected.

## Phase 1 - User and painful scene

Goal: force the target user from abstract segment into a concrete person and scene.

Ask:

- “你的第一个目标用户是谁？给我一个真实或半真实的人：他是谁、在什么场景、最近一次为什么痛。不要说一类人。”

Probe:

- “最近一次你和这个用户聊是什么时候？他说了哪句话？”
- “这个问题发生频率是多少：每天、每周、每月，还是偶发？”
- “这个痛点影响钱、时间、增长、合规、体验，还是某个关键 KPI？”

Exit when:

- There is one concrete user/persona.
- There is one concrete painful scene.
- Pain has frequency and consequence.

## Phase 2 - Substitute and problem reality

Goal: prove the problem exists before discussing features.

Ask:

- “没有你的产品时，他今天怎么解决？包括 Excel、人工、外包、竞品、土办法、忍着不做。”

Probe:

- “这个替代方案最糟糕的一步是什么？”
- “为什么不用市场上最明显的竞品？”
- “他为这个问题付过钱、花过时间、找过人，还是只是抱怨？”

Exit when:

- Substitute is known.
- Substitute failure is specific.
- Evidence level is marked: paid / active workaround / verbal interest / unverified.

## Phase 3 - Validation evidence

Goal: separate facts from founder imagination.

Ask:

- “你做过什么验证？给我具体数字：访谈人数、原型测试、付费、签约、等待名单、复购、留存、流失。”
- “最强的一条证据是什么？最弱的一条假设是什么？”

Evidence ladder:

1. Paid usage / signed contract
2. Repeated active usage
3. LOI / clear procurement process
4. User actively asks for solution
5. Interview complaint only
6. Founder assumption

Exit when:

- Evidence is categorized.
- Top unknowns are listed.

## Phase 4 - Product wedge and MVP

Goal: compress the vision into the smallest testable wedge.

Ask:

- “如果两周内只能做一个最小版本，砍掉 90% 功能，你做哪一个功能？”

Probe:

- “这个功能能不能解决 Phase 1 那个人的那个场景？”
- “为什么先做这个，不是你刚才提到的其他功能？”
- “首版明确不做什么？”

Exit when:

- One narrow MVP exists.
- Non-scope is explicit.
- MVP maps to one painful scene.

## Phase 5 - Positioning and non-obvious insight

Goal: define why this product should exist and why now.

Ask:

- “用 15 个字以内说清楚这个产品。”
- “在这个领域，大多数人相信什么，但你认为是错的？”
- “为什么现在是时机，五年前为什么不行？”
- “你和竞品最不一样的地方是什么？不要用‘更好’这种词。”

Exit when:

- One-sentence positioning exists.
- Differentiation is tied to insight, not adjectives.
- Why-now has a concrete driver.

## Phase 6 - PRD definition

Goal: convert the validated wedge into buildable requirements.

Ask:

- “首版用户从进入到完成核心动作，一共几步？”
- “P0 功能有哪些？每个功能服务哪个用户场景？”
- “成功标准是什么？用户完成什么行为算成功？”
- “最容易失败的边界场景是什么？”

Exit when:

- Core flow is known.
- P0/P1/P2 is known.
- Metrics and acceptance criteria are known.

## Phase 7 - 0-1 validation and launch plan

Goal: plan learning before scaling.

Ask:

- “上线前你要验证哪三个最大假设？”
- “每个假设用什么实验验证？成功阈值是多少？”
- “第一批用户从哪里来？你亲自怎么找到他们？”

Exit when:

- Assumptions and experiments are defined.
- Launch sequence is defined.

## Phase 8 - Growth extension

Use only when the user has MVP/early users or explicitly asks for growth.

Ask:

- “当前北极星指标是什么？”
- “用户第一次获得价值发生在哪一步？”
- “留存靠什么，而不是靠提醒？”
- “收入从哪里来：订阅、交易、硬件、服务、企业采购、广告，还是混合？”

Exit when:

- Acquisition, activation, retention, revenue, and roadmap are defined at a useful level.
